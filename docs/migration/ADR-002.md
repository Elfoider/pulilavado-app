# ADR-002 · Contratos V2 y ensayo de acceso separado

Estado: adoptado para la preparación técnica de fase 2.

La copia de Pulix V2 revisada ya contiene identidad, organización/sede, roles y APIs autorizadas. La aplicación original conserva reglas financieras distintas y consultas globales. Incorporar Firebase Auth delante de esas consultas no las convertiría en operaciones aisladas por sede.

Se mantiene el origen como referencia y se prepara un laboratorio independiente en `demo-pulilavado-contracts`, con Auth Emulator, reglas restrictivas, perfiles/membresías/roles/sedes ficticios y un resumen de lectura por sede. La selección de organización procede del perfil autenticado; los permisos no se autoconceden. Las escrituras de autorización y operación se rechazan desde el SDK del cliente.

El entorno anterior de regresión sigue separado y usa su configuración de emulador heredada. El laboratorio verifica al iniciar que una lectura anónima esté prohibida, para detectar reglas permisivas utilizadas por error. Ninguno admite conectarse a proyectos cloud.

Los repositorios operativos futuros deberán usar los contratos de API y autorización de V2, no el adaptador de lectura de este ensayo. La matriz tipada de las 16 colecciones registra diferencias y bloqueos. Los nombres de rutas son contratos de revisión, no una aprobación para copiar datos.

Consecuencia: puede probarse identidad y aislamiento sin acceso productivo, mientras los contratos de vales/sobres, nómina, pagos mixtos y corte se cierran de forma explícita. La fase 2 de negocio no se declara concluida ni lista para importar hasta resolverlos y revisar una copia consistente. No se reutilizan las pantallas de administración ni el backend de la otra aplicación en este repositorio.
